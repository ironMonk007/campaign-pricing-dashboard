Deal engine assumptions

Editable policy · recalculated immediately

% % · policy range 5–8% % within last 30 days

Proposed prices are discounted from the qualifying reference and do not exceed the same markdown from the current listing. Margin floor = unit cost ÷ (1 − minimum margin − platform fee rate). Standard deals may relax the chosen markdown to a minimum 5% below both the observed median and current listing to meet a feasible margin floor. A floor above the qualifying limit blocks the deal; mega deals never raise the price to meet the floor.

Low G2N: suggest a seller-funded bundle or voucher for evaluation, not a steeper base-price discount. Recent hike flags need verification, not an assumption of seller intent.

Data contract, templates & how updates work

Use an Excel workbook with Products and PriceHistory sheets, or upload those sheets as separate CSV/TSV files. Data is held in memory and resets when you reload or close the page. Upload replaces rows for each supplied sheet; uploading history alone preserves the current Products data. There is no automatic API sync.

Rolling exports: the 67-column Daraz SKU export is also supported. Use daraz_sku as the primary SKU_ID in any supplemental PriceHistory; sku_id is retained separately. L30D orders and GMV are reported fields, not assumed gross/net populations. GMV units and source currency remain unverified without explicit metadata. min_sp_l90d is a reported SP minimum, not verified order-qualified evidence. All rolling recommendations are review-only. The source has no dated window end: changing the analysis date must not reinterpret its 30/60/90-day summaries. Upload standard Products plus actual dated PriceHistory to unlock verified approval.

Products: one row per SKU snapshot. Recommended fields: Seller_ID, Seller_Name, SKU_ID, SKU_Name, UV, Gross_Orders, Net_Orders, Gross_GMV, Net_GMV, Current_Price, Current_Price_Date, Unit_Cost, Min_Gross_Margin_Pct, Fee_Pct, Stock, Active, Currency, Period_Start, Period_End. Percent fields use percentage points (e.g. 25 = 25%). G2N can use orders or GMV, never a mixture. Period dates describe the performance snapshot; this dashboard does not sum multiple daily snapshots.

PriceHistory: Seller_ID, Seller_Name, SKU_ID, Date, Price, Orders, Currency. Price must be a comparable per-unit selling price; Orders identifies gross orders recorded at that price. Cheapest zero-order listings never qualify as the 90-day low. No net-order or voucher-paid inference is made. Use the same currency, variant, pack size, tax and voucher basis throughout. Separate each distinct variant into its own SKU_ID.

All records must identify the seller with Seller_ID or Seller_Name. Completely anonymous files and files that partly omit seller identity are rejected before any calculations. If several sellers are present, select exactly one; others are excluded before any median, score, or total. Conflicting SKU snapshots and price observations are rejected rather than silently duplicated.

The audit window runs from analysis day −90 to day 0 inclusive, using dated observations. The median is an observation median, not a daily-weighted price. Gaps and sparse history are disclosed. A recent-hike alert requires earlier (>30 days ago) and recent evidence (last 30 days), a verified current-price date, and a configurable threshold; it is a suspected markup, not proof of artificiality. Missing current-price dates block current-price campaign approval. The user-selected analysis date is not necessarily the campaign date.

Seller G2N is shown both as mean SKU retention and gross-weighted retention. Summed product UV is not distinct seller traffic. Ranking weights are GMV 30%, gross orders 30%, UV 25%, and conversion 15%, using seller-only percentiles. Globally absent metrics are removed and remaining weights renormalized; a missing value on one SKU still contributes zero. Pure rolling exports use reported L30D GMV and orders, 50% each. Risk and uncertain evidence lower priority, which is shown separately from commercial potential. Mixed schema metrics are not substituted for gross fields. Readiness needs ≥3 distinct history dates and a price observed ≥60 days before the analysis date; this is an evidence-policy proxy, not proof of complete 90-day coverage. Prices and recommendations are rounded to two decimals.

The site downloads a spreadsheet parsing library from the SheetJS CDN. Uploaded files are parsed locally and never transmitted. Do not upload confidential files on an untrusted modified copy of this site.
